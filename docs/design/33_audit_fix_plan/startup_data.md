# startup_data: The startup check and the data files

This workstream makes the startup check fast and makes it check what it does not check today, then moves what the game plays by out of code and into data. It builds four pieces of infrastructure: one parse of each data file on the fast loader, with the source parsed once a check and each scan's answer kept for the process; a table of declarations (data/rules/data_keys.yaml) that holds every id named in data to the table that defines it and every key of a rules file to the code that reads it; a function that says which creatures any road can reach; and a count of tuning numbers typed in code that may only fall, a fence of tools/purity.py beside the others. On those rest the moves themselves, system by system, each with values unchanged. One fault here is met in play today: a war draws dragons and oozes as its hosts one time in three. Left to the owner: which category was meant by 'humanoid', what becomes of six keys that promise rules never built, where 60 unreachable creatures should live, the wording of Maren's line about mana and of two notes, how GOALS.md states the sampling in force, and whether the fight's numbers move now or wait for the balance pass as decided on 2026-11-04.

### STARTUP_DATA-3. A key in a rules file that no game code reads stops the start, and no rule is read with a default that stands in for the data
