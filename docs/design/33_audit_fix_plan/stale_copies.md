# stale_copies: Two copies of one record

The store builds a new object at every load and writes the whole row at every save, so two holders of one record undo each other, and a change made on a held copy that nobody saves is dropped at the next reading. This workstream first widens the stale-save check the world's row already has to every record kind, and adds two checks the audit's instrument proved by hand (a change nobody saves, a reference the scene holds apart from its record), so the suite and the night runs name every remaining case. It then fixes each pair the audit saw with the piece that closes its kind: one seam through which engine code reaches the character's record the scene holds, code handed the scene asking the scene for a person, one object for each person here between two readings of the room, one way for a scene to move trust, and what waits on the player's next line kept in the save by id. Left to the owner: whether a job from someone met on the road is struck when the player walks on, what finishing a request is worth in all, the words of one new line, and whether the larger cure (one live record for each operation) gets a design or the ruling of 2026-11-10 (ruled on one by one) stands.
