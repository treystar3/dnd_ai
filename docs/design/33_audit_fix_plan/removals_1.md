# removals_1: Dead code and unneeded files

This workstream takes out what the game carries and never runs: imports nothing uses, names nothing reaches, helpers only tests call, parameters nothing reads, two retired model steps, a check no call can reach, files tracked for no use, and data keys no code reads. It builds five fences in the suite so the kind cannot come back: one for imports, one for names (with declared tables of what is kept on purpose and why, and of what a named later feature removes), one for unread parameters, one for tracked files, and one rule that no config read falls back to a data table; the lasting cover for data keys is STARTUP_DATA-3's walk, which this feeds. Three of the fences are the census the other part plans as REMOVALS_2-1 (imports, names, files): one census is built, by whichever of the two features is approved, and the others add their removals to its lists. One fault a player can meet is fixed on the way: Maren's figures check passes a level the guild does not have whenever a word stands before "level". Nothing here but the last feature changes what a turn does or saves, so no recording should differ in inputs, state, calls or words; four features edit files under data/ (more may, by the owner's answers) and so move the data hash, and they are meant to land together with one re-stamp of the three kept sessions. Left to the owner: whether hunger and fatigue return, whether the families' fight lines are wired, held or deleted, whether conditional loot properties are still wanted and whether the loot halving moves to data before the balance pass, whether the import of saves from before the database and the dormant server start are retired, a handful of files and small helpers, and when the one re-bless that drops saved fields nothing reads is taken.
