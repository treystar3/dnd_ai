# suite: The test runner and the hooks

This workstream makes the suite quick to trust and stops it writing where it should not. It builds six pieces of infrastructure: a quick run that takes what changed from git and compares it with the tree its own record describes (no baseline checkout, every tracked file, scratch picks nothing); a record that also keeps the files a test read and the folders it listed, so the fence tests are picked; one place that says where the game's logs go, so a test's process logs to a folder of its own; a folder of its own for everything else a test writes (temp folders, saves), with a check that fails a test that writes anywhere else in the repository; a push marker that believes only a full run of this commit on a clean tree; and a runner that uses the machine and keeps its record when it is stopped. Around these are small single-place fixes (the census, the model fence's walk, one ignore line, a wrong path in the bundle workflow) and one clean-up of the 3.5 GiB already left on disk. Nothing here changes the game, a recording or the data hash, and nothing needs the card. Left to the owner: the go for each edit to the owner's own files (.claude/hooks, the suite-runner agent, the feature skill, the bundle workflow, CLAUDE.md), the choices named under the features, the commit of the documents that tracked files cite, and the running of the one clean-up. Every made-up test file that these features' tests run through the real runner prints one check line (`ok   ...`), so each holds under TESTS-2's rule that a test which exits 0 having printed no check line fails, whichever of the two lands first.
