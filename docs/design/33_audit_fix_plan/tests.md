# tests: Tests and recordings that cannot catch what they are for

This workstream mends the checks themselves: a replay that passes when the game stops short, tests that cannot fail or skip in silence, kept recordings whose census reads the lines the script typed, fakes that take what the real thing refuses, and three kinds of test nobody has (each model task failed in turn, a pane command played in a fight, the balance bot's loop run). It builds eight pieces of infrastructure: an end check in tools/rerun.py, one check helper in simlib with a runner that counts checks and skips, a task-failure matrix beside rerun, a "fight in step" comparison, a census helper for kept scripts, syntax-tree readers for the fences, a tracked list of the pinned server's flags, and readers that let a test ask for a line by its key. Three features are the failing test another workstream's fix is built against (task_failure, fight_scene, tools_bots), so they land with those fixes, not before them; where the other workstream already plans the same test or the same runner change (FIGHT_SCENE-3's walk of the command table, SHIPPING-2's skip count, SUITE-2's output folder, SUITE-7's put-back), the feature here says so and builds only what is left. Left to the owner: making stub_party again so it holds what its docstring says, where a task's declared failure lives, whether node goes on the owner's machine, whether a failed lesson ask closes an earlier offer, which modules are held pure, and one run of the pinned server's `--help` (a session may not read runtime/). No feature here changes what the model is asked or allowed to write, so none needs the card.
